# Архитектура — 2.0

## Поток обработки

`gui/main_window.py` выбирает механизм по `SourceDC.source_provider`. Настройки читаются через `utils/config_manager.py`; старый `source_type` поддерживается при чтении. Работа с LDAP при анализе и миграции выполняется вне GUI-потока. Виджеты не используются из рабочих потоков.

- **AD:** `core/analyzer.py` → план и исполнение в `core/migrator.py` → обработчики `core/object_handlers/`. Чтение и запись — `core/ldap_connector.py`, правила исключений — `core/ignore_rules.py`, атрибуты — `config/attribute_mappings.yaml`.
- **FreeIPA:** `core/sources/freeipa.py` читает users/groups accounts, идентификаторы и эффективные права. Методы записи источника запрещены. `core/freeipa_migration.py` подготавливает отдельный план, проверяет назначения/конфликты, создаёт объекты, восстанавливает связи и проверяет результат. Обязательные поля и связи FreeIPA задаёт этот модуль; необязательные профили обрабатываются `core/freeipa_attributes.py` по правилам INI. AD YAML не управляет преобразованиями FreeIPA.

FreeIPA использует `ipaUniqueID`, не подменяя его искусственным AD GUID. Строковое поле истории `source_guid` содержит собственный идентификатор соответствующего провайдера. Источник FreeIPA идентифицируется через `nsUniqueId` контейнера accounts; назначение и созданные объекты — через AD objectGUID.

## История и повторный запуск

`database/migration_db.py` управляет SQLite. Запуски, конфигурации, соответствия, ссылки и ошибки хранятся в общих таблицах; направление изолирует данные разных источников/назначений. `for_source()` задаёт контекст FreeIPA, AD использует контекст пары доменов. Новые конфигурации запусков содержат явный `source_provider` для обоих типов. Старые записи не переписываются предположительными значениями.

Проверенный GUID назначения обязателен для повторного использования и связей. Проверка отслеживает перемещение объекта, но не считает совпавшее имя подтверждением соответствия. Неоднозначная старая история не присваивается новому направлению автоматически. Индекс нормализованного идентификатора ускоряет обращения к отображениям; новые FreeIPA-таблицы не создаются.

GUI сохраняет выбранный файл в `Application.migration_db`. Смена истории закрывает прежнее соединение и сбрасывает план/ссылку на последний отчёт. Выбранный SQLite-файл предварительно проверяется в режиме только чтения. Это выбор существующей истории, а не импорт и не объединение баз.

## Надёжность и границы

Поиск LDAP использует страницы. AD-коннектор дочитывает ranged-атрибуты; FreeIPA проверяет результаты страниц и отказывается от неполных ответов. FreeIPA-план повторно строится перед записью и сравнивается с одобренным планом, независимо от порядка LDAP-ответов. Членство добавляется пакетами, чтение при проверке кэшируется в пределах операции.

Новый пользователь создаётся отключённым. Общий обработчик паролей устанавливает новый пароль с резервными случайными попытками. FreeIPA сохраняет неподтверждённое состояние до установки пароля, чтобы потеря ответа не была принята за успех. Сбой транспорта останавливает дальнейшие записи; повторный запуск проверяет сохранённые соответствия. Междоменной транзакции и автоматического отката нет.

## Интерфейс и проверки

`gui/freeipa_discovery.py` показывает цветной план, ссылки и рекомендации. Исключение выбранных DN сохраняет настройки и требует нового анализа; ошибки идентичности не обходятся. `gui/migration_table.py` реализует выбор строк, CSV-экспорт и выбор базы; таблицы AD используют тот же компонент.

Локализация — gettext, домен `DirectoryObjectMigrator`. `extract_strings.py` извлекает строки и учитывает динамические сообщения, `update_translations.py` формирует каталоги, `compile_translations.py` собирает MO. Переводы редактируются в карте RU генератора.

`tests/run_all.py` запускает проверки LDAP, истории, атрибутов, ссылок, паролей, отказов и GUI. Сценарии реальных стендов и их базы находятся вне поставляемого архива. Поддерживаемые объекты и ограничения — в [README](../README.md).

## Явное пересоздание FreeIPA

`PlannedObject.recreation` содержит прежние GUID/DN, тип и направление только после успешной проверки отсутствия и конфликтов. Подтверждение GUI передаёт эти значения на повторный анализ; `FreeIPAPlan.recreation_requests` входит в отпечаток одобренного плана и конфигурацию реального запуска. Действие `recreate` участвует в построении ссылок и верификации наравне с созданием. Разрешение не сохраняется в INI.

Перед LDAP Add повторно проверяются направление, прежний объект, история и родитель. `MigrationDB.replace_missing_mapping()` атомарно сравнивает прежнее соответствие, меняет GUID/DN и сохраняет запись аудита в `migration_errors` с фазой `recreate` и уровнем INFO. Первоначальный запуск не теряется; новой таблицы нет. Если условие сравнения не выполнено или аудит не записан, обновление SQLite откатывается. Между LDAP Add и SQLite нет общей транзакции, поэтому неопределённые результаты требуют проверки и не принимаются автоматически по имени.

## Необязательные атрибуты FreeIPA

`gui/freeipa_attribute_settings.py` редактирует список правил, `ConfigManager` хранит его как JSON в `FreeIPAAttributeMappings.rows`. Схемы источника и назначения проверяются до чтения дополнительных полей. В `discover(profile_attributes=...)` обязательные проверки прав идентичности/блокировки/ссылок сохраняются, права на необязательные поля проверяются по каждому полю в `AttributeMappings.prepare()`.

`PlannedObject.optional_attributes` отделены от обязательных `attributes`. Правила, ожидаемые значения и предупреждения входят в отпечаток плана. После создания и регистрации GUID новые объекты получают отдельные Modify для необязательных полей. Только определённые серверные коды отказа атрибута допускают продолжение с предупреждением; транспортный сбой или неизвестный исход останавливает запись. LDAP-коннектор сохраняет код результата в `LDAPOperationError.result_code`.

Предупреждения сохраняются в `migration_errors` с уровнем WARNING и фазой `attributes`, показываются в предпросмотре/CSV и HTML/TXT-отчётах. Дополнительные таблицы SQLite не требуются. Повторная проверка необязательных значений сообщает расхождения без автоматической перезаписи существующих профилей. Старый программный вызов FreeIPAMigrator без `attribute_mappings` сохраняет прежнюю фиксированную схему; GUI всегда передаёт сохранённую либо исходную таблицу.

### FreeIPA login allocation

`shorten_long_logins` is an opt-in SourceDC setting. After discovery, the planner allocates <=20-character user names in deterministic source-name/native-ID order, reserves source and historical names, and checks target DN/SAM/UPN collisions. The minimum suffix width is max(3, digits(eligible long users)), growing on overflow. Plan fingerprints include the setting, statistics and generated attributes. Initial mapping insertion atomically stores `freeipa_login` JSON in existing `migration_map.notes`; status updates and explicit recreation retain it. Direction-scoped assignments take precedence over the option on subsequent runs, including missing-target recreation. Analysis/Dry Run never persist assignments. AD naming and group names are unaffected.
