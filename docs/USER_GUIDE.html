Введение

Directory Objects Migrator — инструмент для миграции объектов Active Directory из Microsoft AD в Samba AD.

Возможности

✅ Миграция подразделений (OU)
✅ Миграция пользователей
✅ Миграция групп с членством
✅ Миграция контактов
✅ Сохранение иерархии
✅ Трансформация атрибутов
✅ Отложенное членство (DEFERRED)
✅ Идемпотентные запуски
✅ Режим симуляции (Dry Run)
✅ Детальное логирование
✅ Генерация отчетов (HTML/TXT)

Ограничения

❌ Пароли НЕ мигрируются
❌ DNS зоны не мигрируются
❌ GPO не мигрируются
❌ Компьютеры не мигрируются

Установка

Системные требования

  • ALT Linux (или совместимая система)
  • Python 3.10+
  • Права root для установки

Установка зависимостей

Запустите установочный скрипт:

sudo ./install.sh

Или вручную:

# Установка пакетов
sudo apt-get install python3-module-ldap3 python3-module-PyQt5 \
                     python3-modules-sqlite3 python3-module-yaml

# Компиляция переводов
python3 compile_translations.py

Первый запуск

Запуск приложения

python3 main.py

Или через меню приложений: System → Directory Objects Migrator

Интерфейс

При первом запуске вы увидите главное окно с:

  • Статусом подключений (красный = не настроено)
  • Полем Base DN для указания откуда мигрировать
  • Чекбоксом Dry Run для режима симуляции
  • Кнопками Analyze / Start Migration / Generate Report
  • Окном логов для просмотра процесса

Настройка подключений

Открытие настроек

File → Settings или нажмите Analyze (откроется автоматически, если не настроено)

Вкладка Source DC

Настройки исходного контроллера домена (Microsoft AD):

  • Host / IP Address: IP или hostname контроллера домена
  • Port: 389 (LDAP) или 636 (LDAPS)
  • Domain: Имя домена (например: source.alt)
  • Username: Имя администратора (например: administrator)
  • Password: Пароль администратора
  • Use TLS: Шифрование соединения (рекомендуется)

Кнопка "Test Connection" — проверка подключения.

Вкладка Destination DC

Аналогично для целевого контроллера (Samba AD).

Вкладка Migration Options

Performance:

  • Batch Size: Количество объектов, обрабатываемых за раз (по умолчанию 100)

Password Policy:

  • Random Password: Случайные пароли для пользователей
    • Length: Длина пароля (по умолчанию 12)
  • Fixed Password: Один и тот же пароль для всех пользователей
    • Введите пароль в поле ниже
Важно: Все пользователи создаются в отключенном состоянии (disabled). Администратор должен:
1. Установить финальные пароли
2. Включить учетные записи

Сохранение настроек

Нажмите Save. Адреса, порты, домены и имена пользователей сохраняются в конфигурационный файл, пароли — нет (из соображений безопасности).

Пароли запрашиваются один раз за сеанс работы программы и хранятся только в памяти. Повторные нажатия Analyze и Start Migration пароль не спрашивают. Если пароль оказался неверным, он сбрасывается, и при следующей попытке подключения программа запросит его снова.

Выполнение миграции

Шаг 1: Указать Base DN

В поле Base DN for Migration введите DN контейнера или OU, который нужно мигрировать:

OU=Users,OU=Company,DC=source,DC=alt

Все объекты внутри этого DN (включая вложенные OU) будут мигрированы.

Шаг 2: Режим Dry Run (опционально)

Если хотите протестировать миграцию без фактического создания объектов:

✅ Установите чекбокс Dry Run Mode

В этом режиме:

  • Выполняется анализ
  • Показывается что будет создано
  • Логи пишутся
  • Но объекты НЕ создаются в destination

Шаг 3: Анализ

Нажмите Analyze.

Приложение:

  1. Подключится к обоим контроллерам домена (пароль запрашивается один раз за сеанс)
  2. Просканирует указанный Base DN в исходном домене
  3. Классифицирует объекты (OU, Users, Groups, Contacts)
  4. Сверится с целевым доменом и базой миграции
  5. Покажет окно Preview

Целевой домен опрашивается именно на этом шаге — иначе предпросмотр не смог бы отличить новые объекты от уже существующих.

Окно Preview

Три вкладки:

Planned actions — что произойдёт с каждым объектом:

Метка Значение
CREATE объект будет создан
EXISTS уже перенесён ранее, будет пропущен
CONFLICT есть в целевом домене, но отсутствует в базе миграции — перезаписан не будет
ERROR не удалось классифицировать (нет objectGUID)

Для каждой строки показаны исходный и целевой DN.

Deferred references — ссылки на объекты за пределами области миграции:

  • 🟢 Будет добавлено сейчас — целевой объект уже перенесён, ссылка применится
  • 🟠 Целевой объект ещё не перенесён — потребуется повторный запуск

Objects found

Количество объектов по типам, включая игнорируемые.

Внизу — блок Notes с предупреждениями о конфликтах и напоминанием, что учётные записи создаются отключёнными. Если создавать нечего, здесь указывается конкретная причина: объекты отфильтрованы, по указанному DN ничего нет, всё уже перенесено ранее или всё в состоянии конфликта.

Встроенные контейнеры

По умолчанию встроенные контейнеры (CN=Users, CN=Builtin и подобные) пропускаются, чтобы при сканировании всего домена не переносить служебные объекты. Но если такой контейнер указан явно в поле Base DN, правило для него отключается — считается, что это осознанный выбор.

Base DN Результат
DC=win,DC=test содержимое CN=Users пропускается
CN=Users,DC=win,DC=test содержимое CN=Users переносится
OU=Sales,CN=Users,DC=win,DC=test переносится

Шаг 4: Миграция

После нажатия Start Migration откроется окно Progress:

  • Прогресс-бар (0-100%)
  • Текущая фаза (1/5, 2/5...)
  • Логи в реальном времени
  • Кнопка Cancel для остановки

Повторный запрос пароля не производится — он уже сохранён в памяти на время сеанса.

Фазы миграции:

  1. Phase 0: Analysis (0-20%) — Повторный анализ
  2. Phase 1: Creating OUs (20-40%) — Создание подразделений (от корня к листьям)
  3. Phase 2: Creating objects (40-60%) — Создание пользователей, групп, контактов вместе со всеми атрибутами
  4. Phase 3: Copying attributes (60-80%) — Ничего не делает: атрибуты уже записаны на фазе 2 одной операцией. Фаза оставлена в конвейере как отдельный шаг на случай атрибутов, которые Samba принимает только вторым запросом.
  5. Phase 4: Resolving references (80-95%) — Разрешение ссылок (member, manager), включая отложенные с прошлых запусков
  6. Phase 5: Verification (95-100%) — Сверка количества объектов и проверка оставшихся отложенных ссылок

Шаг 5: Завершение

По завершении:

  • ✅ Success: Миграция завершена успешно
  • ❌ Failed: Произошла ошибка (смотрите логи)

Кнопка Close — закрыть окно прогресса.

Повторные запуски

Идемпотентность

Приложение безопасно запускать повторно с тем же Base DN:

  • ✅ Существующие объекты не перезаписываются
  • ✅ Новые объекты создаются
  • ✅ Отложенные ссылки разрешаются, если целевые объекты теперь существуют

Сценарий: Поэтапная миграция

Первый запуск:

Base DN: OU=Department1,DC=source,DC=alt

Мигрирует пользователей и группы из Department1.

Группа Group1 имеет члена User5 из OU=Department2 — эта ссылка будет DEFERRED (отложена).

Второй запуск:

Base DN: OU=Department2,DC=source,DC=alt

Мигрирует Department2, включая User5.

Третий запуск:

Base DN: OU=Department1,DC=source,DC=alt

Повторный запуск первого DN:

  • Существующие объекты пропускаются (EXISTS)
  • Group1 обновляется: User5 теперь добавляется в группу (был DEFERRED, теперь RESOLVED)

Просмотр статуса

В логах вы увидите:

[SUCCESS] Created user: CN=User1,OU=Department1,DC=dest,DC=alt
[WARNING] CN=User2,OU=Department1,DC=dest,DC=alt - EXISTS
[WARNING] Deferred 1 member references for CN=Group1,...

Генерация отчетов

Создание отчета

После успешной миграции кнопка Generate Report становится активной.

Нажмите Generate Report и выберите формат:

  • Yes: HTML отчет (с графиками и цветами)
  • No: Текстовый отчет (plaintext)

HTML отчет

Содержит:

  • 📊 Статистику в виде карточек
  • 📋 Таблицы по типам объектов
  • 🔗 Отложенные ссылки
  • ⚠️ Конфликты
  • ❌ Ошибки

Отчет откроется в браузере автоматически (если выбрано).

Расположение отчетов

Отчеты сохраняются в:

~/.config/DirectoryObjectsMigrator/reports/

Имя файла:

migration_report_<RUN_ID>_<TIMESTAMP>.html
migration_report_<RUN_ID>_<TIMESTAMP>.txt

Устранение неполадок

Приложение не запускается

Симптом:

ModuleNotFoundError: No module named 'PyQt5' (или ldap3, yaml)

Пояснение: в ALT Linux системные пакеты Python лежат в /usr/lib64/python3/site-packages, которого нет в стандартном sys.path. main.py добавляет этот путь сам, поэтому запускать следует через ./run.sh или python3 main.py, а не импортировать модули проекта вручную.

Решения:

  1. Проверьте зависимости: ./check_dependencies.sh — скрипт использует тот же путь поиска, что и приложение, поэтому его результат совпадает с реальностью
  2. Установите отсутствующие пакеты: sudo ./install.sh

Интерфейс частично на английском

Симптом:

Главное окно переведено, а диалоги — нет

Пояснение: ошибка исправлена (язык сбрасывался при создании главного окна). Если проблема осталась, скорее всего не собраны файлы переводов: 
python3 update_translations.py    # обновить каталоги из исходного кода
python3 compile_translations.py   # собрать .mo

Проверить полноту перевода: python3 update_translations.py --check

Ошибка подключения к DC

Симптом:

"Connection failed" при Test Connection

Решения:

  1. Проверьте IP/hostname контроллера домена
  2. Проверьте порт (389 для LDAP, 636 для LDAPS)
  3. Проверьте сетевую доступность (ping <DC_IP>)
  4. Проверьте credentials (username/password)
  5. Если используется TLS — убедитесь, что DC поддерживает LDAPS
  6. Проверьте firewall на DC

Объекты не создаются

Симптом:

Логи показывают "Created", но объектов нет в destination

Решения:

  1. Проверьте: не включен ли Dry Run Mode?
  2. Проверьте логи на наличие CONFLICT — возможно, объекты уже существуют
  3. Проверьте права администратора в destination DC

Много DEFERRED ссылок

Симптом:

В Preview большое количество "Deferred references"

Пояснение: Это нормально, если группы ссылаются на пользователей из других OU, которые еще не мигрированы.

Решение:

  1. Мигрируйте остальные OU
  2. Запустите повторную миграцию первого DN — DEFERRED ссылки разрешатся автоматически

CONFLICT при повторном запуске

Симптом:

Логи показывают "CONFLICT - exists but not tracked"

Пояснение: Объект существует в destination, но не записан в базу данных миграции (возможно, создан вручную).

Приложение НЕ перезаписывает такие объекты из соображений безопасности. Варианты:

  1. Удалить объект в destination вручную, затем запустить миграцию снова
  2. Оставить как есть — объект будет пропущен

База данных миграции

Расположение:

~/.config/DirectoryObjectsMigrator/migration.db

Если база данных повреждена:

rm ~/.config/DirectoryObjectsMigrator/migration.db
Внимание: История миграций будет потеряна.

Логи

Логи сохраняются в:

~/.config/DirectoryObjectsMigrator/logs/

Имя файла:

migration_<YYYYMMDD_HHMMSS>.log

При проблемах — откройте лог-файл и найдите строки с [ERROR] или [CRITICAL].

Смена языка

Меню: Language → English / Русский

После выбора языка приложение предложит перезапуск. Нажмите Yes.

Безопасность

Пароли

  • ✅ Пароли НЕ сохраняются в конфигурационных файлах
  • ✅ Пароли пользователей создаются случайными
  • ⚠️ Администратор должен установить финальные пароли вручную

Конфигурация

Конфигурационный файл:

~/.config/DirectoryObjectsMigrator/DirectoryObjectsMigrator.ini

Содержит:

  • IP адреса DC
  • Имена доменов
  • Usernames (но НЕ пароли)
  • Настройки миграции

Права доступа

Для миграции требуются права администратора домена на обоих DC (source и destination).
