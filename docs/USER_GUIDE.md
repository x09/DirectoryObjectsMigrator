# Руководство оператора — 2.0

Полная область переноса, таблицы атрибутов и ограничения приведены в [README](../README.md).

## Подготовка

1. Сохраните прежнюю базу истории и убедитесь, что выбран правильный файл. Для продолжения предыдущего переноса нужна именно его история, а не пустая база.
2. В параметрах подключения выберите AD или FreeIPA, задайте источник и Samba AD. Пароли подключения действуют в пределах сеанса.
3. Для AD выберите исходную ветку. Для FreeIPA выберите существующие целевые OU/контейнеры пользователей и групп; пустые поля означают CN=Users назначения. Исходный Base DN в режиме FreeIPA не показывается.
4. Для FreeIPA решите, нужен ли RFC2307, до первого переноса. Персональные группы переносятся только с ним. Подготовьте целевую схему и проверьте уникальность UID/GID.
5. Настройте случайный либо фиксированный пароль создаваемых пользователей. Фиксированный пароль миграции сохраняется в INI; административные пароли подключения не сохраняются.

## Анализ и исправление проблем

Во время фонового анализа отображается индикатор активности. Предпросмотр показывает действия и причины. Зелёные строки — создание, серые — существующие/пропущенные объекты, красные — конфликты/ошибки; отложенные ссылки выделяются оранжевым.

В FreeIPA выберите строку целиком, чтобы прочитать рекомендацию. Если записи уже переносились, кнопка «Выбрать базу истории миграции…» позволяет указать прежний файл и повторить анализ. При независимом конфликте исправьте данные в каталогах или исключите ненужные исходные записи кнопкой «Исключить и повторить анализ». Исключения сохраняются по точному DN, их можно отменить в настройках.

Не исключайте нужных пользователей только ради активной кнопки запуска. Для пользователя с RFC2307 нужна его основная POSIX-группа; пропуск группы может блокировать зависимых пользователей. Повторяющиеся/отсутствующие идентификаторы FreeIPA исправляются в источнике.

Правый клик по таблице → «Сохранить таблицу в CSV…». Сохраняется вся текущая таблица с заголовками, а не только выделенные строки. Вкладку ссылок можно экспортировать отдельно. При импорте CSV выберите UTF-8 и разделитель `;`.

## Запуск и завершение

Проверьте план в Dry Run. При реальном переносе перед записью FreeIPA повторно проверяет план: изменившиеся данные требуют нового анализа. Новые пользователи остаются отключёнными, пароли источника не переносятся.

После завершения прочитайте журнал и сохраните отчёт. Предупреждения о пропущенных ссылках не равнозначны успешному переносу этих связей. Ошибки паролей, создания или проверки необходимо устранить. Если установка пароля FreeIPA-пользователя ранее не подтверждена, сбросьте его средствами администрирования Samba AD и повторите анализ.

Отмена и сетевой сбой не удаляют уже созданные записи. Продолжайте с той же базой истории. Не очищайте базу для устранения конфликтов и не связывайте объекты только по совпадающим именам.

После проверки администратор устанавливает рабочие пароли и включает необходимые учётные записи. Программа не удаляет лишние целевые объекты и не синхронизирует изменения исходных профилей поверх существующих записей.

## Если ранее перенесённый объект удалён из Samba AD

Для FreeIPA выберите прежнюю базу истории, выполните анализ и выделите отсутствующие пользовательские/групповые записи. Кнопка «Пересоздать удалённые объекты…» открывает подтверждение, после которого выполняется повторный анализ. Оранжевое действие «Пересоздать» исполняется только по кнопке запуска миграции. Dry Run ничего не создаёт.

Новая запись получает другой SID/GUID. Права на ресурсы и прежний пароль не возвращаются; поддерживаемые связи восстанавливаются по текущему источнику. Пользователь остаётся отключённым. Перемещённые объекты и чужие записи на прежнем DN не пересоздаются. Для AD это действие пока недоступно. Подробные проверки и ограничения — в разделе пересоздания в README.

## Необязательные поля FreeIPA

На вкладке настроек «Атрибуты FreeIPA» настройте строки «тип → исходное поле → целевое поле», режим значений и включение правила. Сохраните настройки в INI и повторите анализ. В исходную таблицу включён перенос публичных SSH-ключей `ipaSshPubKey → altSecurityIdentities`; настройка чтения ключей SSH/SSSD выполняется отдельно.

Опечатки и неподходящие поля перечисляются на вкладке предпросмотра «Предупреждения по атрибутам». Они не блокируют создание объекта, но соответствующие данные не будут перенесены. Серверный отказ отдельного необязательного поля также фиксируется предупреждением. Проверьте раздел необязательных атрибутов в отчёте: «создан» не означает «скопированы все поля». Существующие профили правилами не обновляются. В режиме AD таблица не применяется.

### Длинные логины FreeIPA

В настройках соединения включите «Сокращать логины пользователей длиннее 20 символов». Анализ покажет статистику и предлагаемые имена. Формат: префикс + `_` + номер минимум из трёх цифр, всего до 20 символов; занятые имена пропускаются. CN, sAMAccountName и UPN получают выбранный логин. Сохранённые в истории назначения не меняются при повторном запуске или пересоздании, даже после выключения опции. Сохраняйте ту же БД истории. Подробнее — в [README](../README.md).
