# Directory Objects Migrator 2.0

Мигратор объектов службы каталога **AD/FreeIPA → Samba AD** с графическим интерфейсом на русском и английском языках. Приложение читает источник по LDAP, проверяет план, создаёт объекты в целевом домене, восстанавливает поддерживаемые связи и проверяет результат.

| Источник | Что переносится в Samba AD |
|---|---|
| Microsoft AD / Samba AD | OU, пользователи, группы, контакты; поддерживаемые атрибуты и ссылки |
| FreeIPA | Незаблокированные пользователи и обычные группы из дерева accounts; персональные группы — только с RFC2307 |

Это перенос объектов, а не репликация домена. Исходный каталог не изменяется. Целевые объекты не удаляются, одноимённые записи не заменяются и не присваиваются автоматически. Для ранее перенесённых объектов с подтверждённым соответствием могут добавляться недостающие связи. Поэтому операция не ограничивается LDAP Add: для новых пользователей устанавливается пароль, для поддерживаемых связей выполняется LDAP Modify.

## Что нового в 2.0

- Переключатель источника AD/FreeIPA и отдельный механизм миграции FreeIPA.
- Выбор существующих целевых OU/контейнеров отдельно для пользователей и групп FreeIPA. Поле исходного Base DN показывается только в режиме AD.
- Перенос профиля пользователей FreeIPA, обычных и вложенных групп, руководителей и основного POSIX-членства. Опциональный RFC2307 и персональные группы с префиксом `ipa-pg-`.
- Редактор соответствий необязательных атрибутов FreeIPA с сохранением в INI, проверкой схем и предупреждениями вместо отказа создания объекта. Публичные SSH-ключи: `ipaSshPubKey → altSecurityIdentities`.
- Проверка идентификаторов, прав чтения, схемы RFC2307, целевых контейнеров и конфликтов до записи. Повторная проверка плана перед миграцией.
- Явное пересоздание удалённых пользователей и групп FreeIPA по истории: подтверждение, новый SID/GUID, восстановление поддерживаемых связей и журнал смены соответствия.
- Изоляция истории по типу источника и идентификаторам каталогов. В новых запусках явно сохраняется `source_provider=ad` или `freeipa`.
- Цветной предпросмотр FreeIPA, выделение строк целиком, пояснения к ошибкам, исключение выбранных объектов с повторным анализом и выбор существующей базы истории.
- Экспорт таблиц предпросмотра AD/FreeIPA через правую кнопку мыши в CSV: все строки текущей таблицы, UTF-8 с BOM, разделитель `;`.
- Фоновый анализ с индикатором активности, прогресс миграции, проверка значений атрибутов и членства, обработка отмены и сбоев соединения.

История предыдущих версий: [CHANGELOG.md](CHANGELOG.md).

## Установка и запуск

Требуются Python 3.10+, PyQt5 5.15.10+, ldap3 2.9+, PyYAML 5.4+ и модуль SQLite Python. Для пересборки переводов нужен `msgfmt` из gettext. Основная целевая платформа пакета — ALT Linux.

Установка зависимостей в ALT Linux:

```bash
sudo apt-get install python3-module-PyQt5 python3-module-ldap3 python3-module-yaml python3-modules-sqlite3 gettext-tools
```

Запуск из распакованного архива:

```bash
./check_dependencies.sh
./run.sh
```

Для других окружений зависимости перечислены в `requirements.txt`. Скрипт `install.sh` устанавливает зависимости ALT Linux и создаёт ярлык для запуска из текущей папки; после этого папку нельзя перемещать без обновления ярлыка. В исходниках также есть `directory-objects-migrator.spec` для ALT Linux: версия 2.0, исходный архив `DirectoryObjectsMigrator-v2.0.tar.gz`. Готовый RPM в исходный архив не входит.

## Порядок работы

1. Откройте параметры подключения. Выберите тип источника и задайте сервер, домен, порт, учётную запись и пароль для источника и Samba AD. Для FreeIPA допустим простой логин или полный DN пользователя. Исходной записи нужны права чтения переносимых данных; целевой — права создания объектов, установки паролей и изменения поддерживаемых связей.
2. Для **AD** задайте исходный Base DN вручную либо выберите одну ветку в дереве. В область входят поддерживаемые объекты всех её вложенных веток. Структура DN переносится с заменой суффикса домена.
3. Для **FreeIPA** укажите существующие целевые OU/контейнеры отдельно для пользователей и групп. Кнопки «Выбрать…» открывают дерево Samba AD. Пустое поле означает `CN=Users` целевого домена. Включите RFC2307 до первого переноса, если он нужен.
4. Выберите случайные пароли или общий фиксированный пароль. Новые пользователи создаются отключёнными. Определите необходимые исключения.
5. Нажмите «Анализ». Он выполняется в фоне; индикатор активности означает, что идёт чтение/проверка, а не известный процент готовности LDAP-запроса. Для FreeIPA без настроенного назначения доступен только просмотр источника.
6. Просмотрите действия, причины и ссылки. При необходимости сохраните таблицу через её контекстное меню. Режим Dry Run позволяет проверить план без записи объектов в целевой каталог.
7. Запустите миграцию, затем изучите журнал и отчёт. Включение пользователей и выдачу рабочих паролей выполняет администратор после проверки результата.

Отмена не откатывает уже выполненные операции. При повторном запуске используйте ту же базу истории: приложение проверит сохранённые соответствия и обработает оставшиеся действия.

## Если запуск FreeIPA заблокирован

Конфликты и ошибки не позволяют начать перенос. Цвет строки показывает действие; выделение строки открывает полную причину и рекомендацию.

| Ситуация | Что делать |
|---|---|
| Объект уже переносился, но отображается конфликт имени/ID | Нажать «Выбрать базу истории миграции…» и указать базу именно того переноса. После выбора анализ повторится. Один и тот же домен в новом профиле без прежней базы не подтверждает идентичность объектов. |
| В целевом домене находится другой одноимённый объект | Исправить имена/данные средствами администрирования либо исключить исходный объект. Автоматического объединения и перезаписи нет. |
| Часть объектов не нужна | Выделить строки и нажать «Исключить и повторить анализ». Сохраняются точные DN; исключение можно убрать в настройках. Зависимые пользователи/группы могут требовать отдельного решения. |
| Нет прав чтения, некорректный логин, неоднозначная основная группа | Исправить права или данные, затем повторить анализ. Кнопка настроек доступна прямо в предпросмотре. |
| Отсутствует или повторяется `ipaUniqueID` | Исправить идентификатор в источнике. Такие ошибки нельзя обойти выбором одноимённого целевого объекта или исключением одной из дублирующих строк. |
| Существующие RFC2307-атрибуты отличаются | Проверить первоначальный режим переноса и значения UID/GID. Программа не обновляет их автоматически. |
| Ранее не подтверждена установка пароля FreeIPA-пользователя | Проверить пользователя в Samba AD и сбросить его пароль средствами администрирования, затем повторить анализ. |

Очистка истории не устраняет конфликт: она удаляет сведения о проверенных соответствиях. Если прежней базы нет, требуется разбор объектов администратором; автоматического «принять всё по имени» в программе нет.

## Пересоздание удалённых объектов FreeIPA

Функция доступна **только для пользователей и групп при источнике FreeIPA**. Это создание нового объекта по актуальным данным источника, а не восстановление удалённой записи из корзины AD.

| Режим миграции | Пересоздание удалённых объектов |
|---|---|
| FreeIPA → Samba AD | Доступно по истории переноса, после явного подтверждения и повторного анализа. |
| Microsoft AD / Samba AD → Samba AD | Не реализовано. Кнопки пересоздания нет; отсутствующий или заменённый объект из истории автоматически не создаётся заново. |

1. Выберите базу истории первоначального переноса и нажмите «Анализ». В пустой или чужой истории одноимённые объекты остаются конфликтами: пересоздание не позволяет принять их по имени.
2. Выделите отсутствующий объект (либо несколько таких строк) и нажмите **«Пересоздать удалённые объекты…»**. Кнопка доступна, только если объект отслеживается в выбранном направлении, его прежний GUID не найден в домене и проверки не выявили занятого DN, конфликтов или недоступного родителя.
3. Прочитайте подтверждение. По умолчанию выбран отказ. В подробностях указаны исходный DN, планируемый целевой DN и прежний GUID. Подтверждение **не создаёт объект**, а запускает новый анализ.
4. Проверьте обновлённый план: появится отдельное действие **«Пересоздать»**, выделенное оранжевым. Можно выполнить Dry Run. Реальная запись выполняется только после «Начать миграцию».

Объект создаётся в прежнем контейнере из истории, с именем и поддерживаемыми атрибутами актуального источника. Изменение текущего контейнера по умолчанию в настройках не переносит пересоздаваемый объект в другое место. Прежний контейнер должен существовать. Перемещённый объект, найденный по прежнему GUID, используется как существующий; он не пересоздаётся. Запись с другим GUID на прежнем DN блокирует операцию и не заменяется.

**Новый SID/GUID не восстанавливает прежнюю идентичность.** ACL, права на файлы/ресурсы, SIDHistory, прежние пароли и членство, добавленное только в целевом домене, не восстанавливаются. Пользователь создаётся отключённым, получает новый пароль по текущим настройкам, основная Windows-группа остаётся Domain Users. Поддерживаемое членство, вложенные группы и ссылки на руководителей восстанавливаются из текущего плана FreeIPA по проверенным соответствиям. Исключённые или недоступные связи по-прежнему не переносятся.

Разрешение относится к конкретным объектам, направлению и прежним GUID/DN, не сохраняется как постоянная настройка INI. Обычный новый анализ снова требует подтверждения. Перед созданием повторно проверяются план, история, отсутствие прежнего объекта, родитель и конфликты. Если история изменилась, прежний объект появился или DN оказался занят, операция останавливается.

После подтверждённого создания история атомарно меняет соответствие на новый GUID и записывает прежний/новый GUID и DN в журнал запуска SQLite. Сохраняется связь с первым переносом. Если создать объект не удалось, прежнее соответствие остаётся. При ошибке установки пароля новое соответствие сохраняется как неподтверждённое по паролю, чтобы следующий запуск не создавал ещё одну запись. Общей транзакции между LDAP и SQLite нет: при потере ответа или сбое записи истории уже созданный объект может требовать ручной проверки. Автоматического присвоения такой записи по имени нет.

## FreeIPA: область переноса

Для домена `ipa.example` читаются:

- Пользователи: `cn=users,cn=accounts,dc=ipa,dc=example`, класс `posixAccount`.
- Группы: `cn=groups,cn=accounts,dc=ipa,dc=example`, классы `ipaUserGroup`, `posixGroup`, `ipaExternalGroup`; external-группы обнаруживаются, но исключаются.

Переносятся только незаблокированные пользователи: `nsAccountLock=TRUE` исключает запись. Отсутствующий атрибут при подтверждённых правах чтения трактуется как отсутствие блокировки. Это не проверка срока действия пароля, последнего входа или фактической активности человека.

Источник проверяется по `nsUniqueId` контейнера accounts, объект — по `ipaUniqueID`, назначение — по GUID домена и объектов. Читаются страницы LDAP; при ошибке или неполном ответе анализ не выдаёт частичные данные за полный результат. Проверка прав использует Get Effective Rights сервера FreeIPA/389 DS. Приложение не может обнаружить записи, полностью скрытые правами доступа: учётная запись должна видеть всю нужную область.

OU FreeIPA не переносятся и не строятся из атрибутов пользователей. Все пользователи помещаются в выбранное назначение пользователей, группы — в назначение групп. Целевые контейнеры должны существовать заранее.

### Поля пользователей FreeIPA

Ниже приведены соответствия по умолчанию. Необязательные поля профиля можно изменить на вкладке «Атрибуты FreeIPA»; идентичность, состояние, пароли, ссылки и поля RFC2307 задаёт приложение.

| Источник | Назначение / правило |
|---|---|
| `uid` | `cn`, RDN `CN=…` и `sAMAccountName`. Исходный `cn` не используется как имя целевой записи. |
| `uid` + домен назначения | `userPrincipalName = uid@целевой.домен`; исходный Kerberos principal не копируется. |
| `givenName`, `sn`, `displayName`, `title` | Одноимённые атрибуты без замены значений. |
| `ou` | `department`; это поле профиля, а не создание OU. |
| `street` | `streetAddress`. |
| `l`, `st`, `postalCode`, `employeeNumber`, `employeeType` | Одноимённые атрибуты. |
| `description` | `description`, также для групп. |
| `mail` | Основной адрес в `mail`, остальные в `otherMailbox`. Домен почты **не заменяется**. |
| `telephoneNumber`, `mobile` | Основной номер в одноимённом атрибуте, остальные в `otherTelephone` / `otherMobile`. |
| `ipaSshPubKey` | Публичные ключи OpenSSH в `altSecurityIdentities`, все значения; настройка SSH-клиентов выполняется отдельно. |
| `manager` | Ссылка на перенесённого и проверенного пользователя. Несколько руководителей не представимы одним AD-атрибутом и блокируют запись. |
| `uidNumber`, `gidNumber`, `loginShell` | Только при включённом RFC2307. |
| Состояние/пароль | Новая отключённая запись (`userAccountControl=514`), новый пароль; основная Windows-группа `Domain Users` (`primaryGroupID=513`). |

Для многозначных почты и телефонов выбирается уже перенесённое основное значение, если оно ещё присутствует в источнике; иначе для почты предпочтителен `uid@исходный.домен`, если он есть, затем первое значение при сортировке. Остальные значения не теряются. Отсутствующие поля не заполняются вымышленными значениями.

Мигратор проверяет логин пользователя на совместимость с AD, включая длину `sAMAccountName` не более 20 символов. Это прикладное ограничение совместимости, а не предел хранения строки в LDAP-схеме (`rangeUpper=256`). В FreeIPA максимальная длина логина по умолчанию составляет 32 символа и настраивается через `ipa config-mod --maxusername` (до 255). Для CN действует ограничение 64 символа.

#### Сокращение длинных логинов FreeIPA

В настройках соединения FreeIPA есть опция **«Сокращать логины пользователей длиннее 20 символов»**; по умолчанию она выключена. Без неё длинные логины блокируют перенос соответствующих пользователей. Для AD эта опция не применяется.

Анализ показывает число длинных логинов среди прочитанных пользователей, число доступных для переноса (без заблокированных и исключённых), количество новых сокращений и имён, сохранённых в истории. Предлагаемый `sAMAccountName` и целевой DN видны в таблице, которую можно выгрузить в CSV до миграции.

Алгоритм: начало исходного логина + `_` + номер, всего не более 20 символов. Для номера резервируется не менее трёх цифр; при 1000 доступных длинных логинах — четыре. Лишние подчёркивания в конце префикса убираются. Новые пользователи обрабатываются в порядке исходных логинов и `ipaUniqueID`, поэтому порядок LDAP-ответа не влияет на результат. При 152 длинных логинах первые два пользователя могут получить:

```text
ivanov_ivanovich_petrovsky   → ivanov_ivanovich_001
ivanov_ivanovich_sidorovsky  → ivanov_ivanovich_002
```

Занятые варианты пропускаются: проверяются имена пользователей и групп источника, сохранённые назначения из истории, а также DN, `sAMAccountName` и UPN целевого домена. При исчерпании разрядности номер увеличивается вместе с разрядностью, а префикс сокращается. Ошибки RFC2307 и другие конфликты этим механизмом не устраняются.

У нового пользователя выбранное имя используется для CN, `sAMAccountName` и части UPN до `@`. Исходный FreeIPA не изменяется; почтовые адреса и прочие профильные поля переносятся по своим правилам, без подстановки сокращённого логина. Имена групп не сокращаются.

При создании объекта назначение сохраняется в SQLite вместе с `ipaUniqueID`, GUID цели и направлением миграции (в `migration_map.notes`, без изменения схемы БД). Повторный запуск, добавление новых пользователей, выключение опции и явно подтверждённое пересоздание используют сохранённое имя. Поэтому необходимо сохранять и выбирать ту же базу истории. Анализ и Dry Run не записывают назначения. Если после предпросмотра имя займёт другой объект, требуется новый анализ; существующие объекты не переименовываются и не принимаются за перенесённые по совпадению имени.

Опция исправляет только превышение длины. Недопустимые символы и прочие некорректные имена по-прежнему показываются как ошибки в плане.

### Настраиваемые соответствия атрибутов

Откройте **Настройки подключения → Атрибуты FreeIPA**. В режиме AD вкладка недоступна и её правила не применяются. В таблице задаются:

| Столбец | Значение |
|---|---|
| Включено | Применять ли правило. Отключённые строки сохраняются, но не исполняются. |
| Тип | Пользователь или группа. |
| Атрибут FreeIPA | Исходное LDAP-имя, например `sn`, `departmentNumber`, `ipaSshPubKey`. |
| Атрибут Samba AD | Целевое LDAP-имя, например `sn`, `department`, `altSecurityIdentities`. |
| Значения | Все значения, основное значение либо остальные значения. |

Можно добавлять и удалять строки, изменять имена полей и восстановить исходную таблицу. После нажатия «Сохранить» правила записываются как JSON в ключ `rows` раздела `[FreeIPAAttributeMappings]` основного INI. Если раздела ещё нет, используется исходная таблица; сохранённая пустая таблица означает отсутствие необязательных полей. Конфигурация правил также включается в историю реального запуска. После изменения требуется новый анализ.

Имена проверяются без учёта регистра по доступным схемам **обоих каталогов**. Обрабатываются текстовые, целочисленные и логические значения; произвольные бинарные данные и DN-ссылки через эту таблицу не преобразуются. Несколько правил на одно целевое поле одного типа объекта считаются неоднозначными: все такие правила пропускаются с предупреждением.

При опечатке, неизвестном/защищённом атрибуте, неподтверждённых правах чтения или несовместимом значении **пропускается поле, а не весь объект**. Причины видны в предпросмотре на вкладке «Предупреждения по атрибутам», которую можно сохранить в CSV. Обязательные проверки идентификаторов, блокировки, конфликтов, связей и RFC2307 сохраняются: их ошибки могут блокировать перенос.

При создании сначала записывается объект с обязательными управляемыми приложением полями, затем необязательные атрибуты записываются отдельно. Если сервер явно отклонил одно поле из-за схемы, значения или прав, остальные могут быть перенесены, объект остаётся созданным. В журнале, SQLite и HTML/TXT-отчёте указывается поле и предупреждение; итог — «Завершено с предупреждениями». Значения отклонённых полей не включаются в диагностическое сообщение. При обрыве соединения или неподтверждённом результате записи последующие записи останавливаются.

Правила действуют при **создании и явном пересоздании**. Они не дописывают и не перезаписывают поля уже существующих объектов. При повторном запуске расхождения необязательных атрибутов сообщаются как предупреждения; обязательные атрибуты и идентичность по-прежнему проверяются строго. Успешное создание с предупреждением не означает, что все данные перенесены.

Режим «Все значения» ничего не обрезает: если целевое поле однозначное, а источник содержит несколько значений, поле пропускается с предупреждением. «Основное значение» выбирает одно значение по правилам почты/телефонов, описанным выше; «Остальные значения» переносит набор без него. В исходной таблице пары `mail/otherMailbox`, `telephoneNumber/otherTelephone`, `mobile/otherMobile` сохраняют весь набор.

GUID/SID, имена входа, `userAccountControl`, пароли, состав групп, руководители и поля RFC2307 нельзя переопределять в этой таблице. Секреты FreeIPA также исключены. Для `altSecurityIdentities` разрешено только соответствие из `ipaSshPubKey` пользователей с проверкой формата публичных ключей OpenSSH; сертификатные/Kerberos-сопоставления через это правило не создаются.

Хранение SSH-ключа не включает SSH-аутентификацию автоматически. Например, SSSD должен читать ключи из выбранного атрибута (`ldap_user_ssh_public_key = altSecurityIdentities`); интеграцию SSH/SSSD и правила доступа администратор настраивает отдельно. См. [описание параметра SSSD](https://github.com/SSSD/sssd/blob/master/src/man/sssd-ldap-attributes.5.xml).

### Группы и связи FreeIPA

- Обычные POSIX и non-POSIX группы создаются как глобальные группы безопасности AD (`groupType=-2147483646`). Имя берётся из `cn`, описание сохраняется.
- Прямое и вложенное членство переносится через `member`. Обратные ссылки формирует целевой каталог.
- Основное POSIX-членство восстанавливается по `gidNumber`, даже если пользователя нет в явном `member` исходной группы. Это обычное членство в целевой группе, а не изменение `primaryGroupID` Windows.
- Персональные группы переносятся **только с RFC2307**, только для включённых в перенос владельцев. Их имена получают префикс `ipa-pg-`, чтобы не конфликтовать с пользовательским логином. Механизм автоматического управления персональными группами FreeIPA не переносится.
- Связи с исключёнными объектами пропускаются с причиной. Недоступные или неподтверждённые цели остаются отложенными и отображаются в результате. Посторонние уже существующие участники целевых групп не удаляются.

### RFC2307

Режим опционален. Переносятся `uidNumber`, `gidNumber`, `loginShell` пользователей и `gidNumber` POSIX-групп. Проверяется наличие целевых атрибутов схемы, обязательных исходных значений, допустимый диапазон чисел `0…2147483647` и конфликты идентификаторов.

UID пользователя и GID группы должны быть уникальными в соответствующем пространстве идентификаторов; совпадение GID пользователя с его группой ожидаемо. При включённом RFC2307 основная POSIX-группа пользователя должна также входить в перенос. Существующие отличающиеся значения не перезаписываются.

Программа не настраивает RFC2307/idmap/SSSD на клиентах и серверах и не переносит владельцев файлов. Режим нужно выбрать до первоначальной миграции; его последующее включение не дополняет автоматически уже созданные записи. `homeDirectory` FreeIPA не входит в исходную таблицу. При необходимости можно явно добавить соответствие `homeDirectory → unixHomeDirectory`; приложение проверит целевую схему, но не преобразует сам путь и не переносит файлы.

### Что из FreeIPA не переносится

- Заблокированные пользователи; staged/preserved users вне основного дерева accounts.
- Административные записи `admin`, `trust admin`; системные группы `admins`, `trust admins`, `ipausers`, `editors`, `default smb group`.
- External-группы, внешние SID, доверия и внешние субъекты безопасности.
- Персональные группы без RFC2307 и группы исключённых владельцев.
- OU, контакты, компьютеры, хосты, службы, сертификаты и ключи Kerberos.
- HBAC, sudo, роли/делегирование администрирования, SELinux mappings, automount и другие политики FreeIPA.
- Исходные пароли/хеши, сроки и политики паролей, исходные SID/SIDHistory, ACL и GPO.
- Поля вне включённых правил соответствий. Например, `departmentNumber`, `homeDirectory`, `gecos` по умолчанию не копируются, но для них можно задать подходящие соответствия. Произвольного копирования всей LDAP-записи нет.

## Особенности AD → Samba AD

**Пересоздание удалённых объектов в этом режиме не поддерживается.** Если ранее перенесённый объект удалён из целевого домена, приложение сообщает об отсутствующем или заменённом объекте из истории и не создаёт его заново. Очистка истории не является восстановлением объекта и лишает приложение проверенных соответствий.

Сохраняется перенос OU, пользователей, групп и контактов. Перечни атрибутов и преобразований находятся в [config/attribute_mappings.yaml](config/attribute_mappings.yaml); системные исключения определяются также кодом правил и настройками. UPN и подходящие суффиксы почтовых атрибутов AD преобразуются для целевого домена. Поддерживаются `member`, `manager`, `managedBy`, в том числе ссылки OU.

**Контейнеры не создаются.** Если выбран контейнер или объекты находятся внутри контейнера, соответствующий контейнер должен уже существовать в целевом домене: тогда поддерживаемые объекты переносятся в него. OU создаются по плану. Отсутствующий целевой родитель отображается как проблема до создания зависимых объектов.

При выборе корня домена обычные пользователи и группы из `CN=Users` включаются в перенос. Встроенные и служебные объекты исключаются; DNS-группы `DnsAdmins` и `DnsUpdateProxy` не копируются. Компьютеры и `foreignSecurityPrincipal` не переносятся; ссылки на такие объекты отмечаются как пропущенные, а не как успешно разрешённые.

Поддерживаются LDAP-пагинация и полное чтение `member;range=…` больших AD-групп с проверкой целостности. Системные GUID/SID генерирует назначение. Исходные пароли, SIDHistory, ACL, GPO, доверия, Exchange и полный набор флагов/политик учётной записи не воспроизводятся. Новые пользователи создаются отключёнными, с новым паролем и основной группой Domain Users.

## Пароли, история и результаты

Пароль нового пользователя может быть случайным или фиксированным и должен удовлетворять фактической политике назначения. При отказе сервера программа фиксирует причину и пробует до трёх новых случайных паролей, в том числе после отказа фиксированного. Значения паролей не включаются в журнал и отчёт. Если использован случайный пароль, администратор задаёт рабочий пароль перед выдачей учётной записи; программа не служит хранилищем сгенерированных паролей.

Пароли подключения к каталогам остаются в памяти сеанса и в INI не сохраняются. **Фиксированный пароль для создаваемых пользователей, если выбран этот режим, сохраняется в разделе Migration INI**; это отдельный параметр, не пароль подключения.

По умолчанию профиль находится в `~/.config/DirectoryObjectsMigrator/`:

| Файл/каталог | Назначение |
|---|---|
| `DirectoryObjectsMigrator.ini` | Подключения без административных паролей, `SourceDC.source_provider`, режим переноса, исключения, таблица `FreeIPAAttributeMappings.rows`, выбранный путь истории `Application.migration_db` |
| `migration.db` | История запусков, соответствия объектов, отложенные/пропущенные ссылки, ошибки и результаты проверок |
| `logs/` | Журналы |
| `reports/` | Сохранённые отчёты |

Старый параметр INI `source_type` читается для совместимости; при сохранении заменяется на `source_provider`. Без обоих параметров выбирается AD. Базу можно выбрать в настройках либо в предпросмотре FreeIPA; её путь сохраняется в INI.

SQLite хранит **несколько запусков и направлений**, а не только последнюю миграцию. Таблицы общие, данные разделяются направлением: для AD — пара GUID доменов, для FreeIPA — тип источника, идентификатор экземпляра FreeIPA и GUID целевого домена. В новом `run_configurations.options_json` явно записывается тип источника; исторические записи старых версий могут не иметь этого поля. База не является полной резервной копией LDAP-каталогов. Смена домена не требует её очистки.

Повторное использование объекта требует подтверждённого соответствия идентификаторов. Удаление/подмена отслеживаемого объекта и совпадение имени посторонней записи не разрешаются автоматической перезаписью. Сохраняйте базу вместе с журналами: без неё повторный перенос может показать конфликты уже созданных записей.

Проверка результата сопоставляет конкретные объекты, переносимые значения и связи, а не только итоговые количества. «Завершено с предупреждениями» требует просмотра причин (например, исключённый участник группы); «завершено с ошибками» означает невыполненные действия или провал проверки. Неустранённые ссылки перечисляются отдельно. Изменение источника или назначения во время работы может потребовать нового анализа и повторного запуска; общей транзакции между двумя каталогами нет.

## Проверка исходников

```bash
QT_QPA_PLATFORM=offscreen python3 tests/run_all.py
python3 update_translations.py --check
python3 extract_strings.py
```

Автоматические проверки покрывают AD и FreeIPA, изоляцию истории, конфликты, исключения, атрибуты, связи, крупные группы, отмену, сбои и GUI. FreeIPA → Samba AD проверялся также на отдельном стенде: первоначальный перенос пользователей/обычных/персональных групп и повторный запуск без повторного создания. Это не заменяет проверку конкретной схемы, прав и данных вашей организации.
