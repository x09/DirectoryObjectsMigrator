# Directory Objects Migrator 1.3

Инструмент для миграции объектов Active Directory из Microsoft AD в Samba AD.

## Изменения в версии 1.3

- Обычные объекты из `CN=Users` включаются при миграции от корня домена.
- Анализ и подготовка плана выполняются в фоне с индикатором активности.
- Исправлены переводы сообщений этапов и пояснение пропусков в предпросмотре.

Группы `DnsAdmins` и `DnsUpdateProxy` в стандартном `CN=Users`, с соответствующим
`sAMAccountName`, считаются служебными и не переносятся. Целевые группы не меняются;
их членство автоматически не копируется. Числовые RID 1101/1102 не исключаются.

Ссылки на компьютеры, ForeignSecurityPrincipals и явно исключённые объекты
показываются во вкладке «Пропущенные ссылки» с причиной, а не как DEFERRED.
Их пропуск отражается предупреждениями в итоговом отчёте; членства в целевом
домене не появляются. Уже накопленные DEFERRED-записи таких ссылок при обычном
запуске выводятся из очереди, но сохраняются в SQLite с причиной в поле `notes`
(`SKIPPED:`), без отметки успешного разрешения. Dry Run историю не меняет.
Не найденные или недоступные для чтения объекты не объявляются неподдерживаемыми.

База SQLite версии 1.2 совместима с 1.3: сохраняйте её для повторных запусков
и разрешения отложенных ссылок. Новых изменений схемы в 1.3 нет.

## Возможности

- Миграция пользователей, групп, организационных подразделений (OU), контактов
- Сохранение иерархии подразделений
- Перенос атрибутов объектов (кроме системных и паролей)
- Обработка ссылочных атрибутов (member, manager, managedBy)
- Повторные запуски с проверкой GUID и разрешением отложенных ссылок
- Инкрементальная миграция с tracking через SQLite
- Отложенное (DEFERRED) членство в группах для объектов вне области миграции
- Одиночный выбор ветки из дерева домена с фоновой загрузкой и индикацией
- Постраничный анализ каталогов и полное чтение больших групп (`member;range=...`)
- Проверка целевых родителей и конфликтов DN, sAMAccountName и UPN
- Верификация конкретных объектов, атрибутов и прямого состава групп
- Графический интерфейс на PyQt5
- Детальное логирование и отчеты

## Требования

### Системные пакеты (ALT Linux)
```bash
apt-get install python3-module-ldap3 python3-module-PyQt5 python3-modules-sqlite3 python3-module-yaml
```

### Python версия
- Python 3.10+

## Запуск из исходников

Распакуйте `DirectoryObjectsMigrator-v1.3.tgz` и выполните:

```bash
cd DirectoryObjectsMigrator-v1.3
python3 main.py
```

## Архитектура

### Поэтапная миграция

1. **Анализ (Discovery)**: Сканирование source домена, классификация объектов
2. **Создание OU**: Создание иерархии организационных подразделений
3. **Создание объектов**: Users, Groups, Contacts (без ссылочных атрибутов)
4. **Перенос атрибутов**: Заполнение обычных атрибутов
5. **Ссылочные атрибуты**: Обработка member, manager, managedBy с DEFERRED tracking
6. **Верификация**: Проверка результатов миграции

## Особенности реализации

### Поддерживаемые объекты и контейнеры

Мигрируются только организационные подразделения (OU), группы, пользователи и
контакты. Контейнеры (`objectClass=container`, например `CN=Users`) автоматически
не создаются и не преобразуются в OU.

При выборе корня домена обычные пользователи и группы из `CN=Users` также
включаются в миграцию. Встроенные учётные записи и группы по-прежнему исключаются
по SID и системным признакам.

Если соответствующий контейнер уже существует в целевом домене, поддерживаемые
объекты из исходного контейнера будут перенесены в него с учётом правил исключения
и конфликтов. Сохраняется путь объекта, заменяется только доменная часть DN.
Например, объекты из `CN=Users,DC=source,DC=alt` переносятся в
`CN=Users,DC=dest,DC=alt`.

Если контейнер или промежуточный родительский контейнер отсутствует в целевом
домене, создание объектов внутри него завершится ошибками. Перед миграцией
необходимо обеспечить наличие соответствующего пути в целевом домене.

### Пароли пользователей

Исходные пароли не читаются и не переносятся. Все новые пользователи создаются
отключёнными (`disabled`). Можно задать фиксированный пароль либо создавать
случайные пароли: по умолчанию 12 символов, с обязательными строчными и прописными
буквами, цифрами и специальными символами. Учитываются выбранная длина и доступное
для чтения значение `minPwdLength` целевого домена.

Пароль должен соответствовать фактической политике целевого домена. В интерфейсе
приведены исходные настройки Samba AD: сложность включена, минимальная длина 7,
история 24 пароля, минимальный/максимальный возраст 1/42 дня, хранение открытого
текста выключено; порог блокировки 0, длительность блокировки и сброс счётчика
30 минут. Это справочные значения: приложение не меняет политику домена.

При отказе установки пароля выполняется до трёх попыток с новыми случайными
паролями, в том числе после отказа фиксированного пароля. Используется `unicodePwd`.
Причины отказов и результаты фиксируются в логах и отчётах без значений паролей.
Успешная резервная установка отмечается предупреждением; исчерпание попыток —
ошибкой. При повторном запуске повторяется незавершённая установка для проверенного
по GUID объекта; успешно заданные пароли не сбрасываются.

### UPN и Email
- Автоматическая замена domain суффикса: user@source.alt → user@dest.alt

### Идентификация объектов и конфликты

SQLite хранит соответствия `objectGUID` исходных и целевых объектов отдельно для
каждой пары доменов, определяемой по GUID корней. Перед повторным использованием
соответствия проверяется GUID целевого объекта; переименованный или перемещённый
объект ищется по GUID. Отсутствующий или подменённый объект блокирует использование
старого соответствия.

Предварительный план и создание проверяют целевой родительский путь, занятый DN,
`sAMAccountName` и преобразованный UPN в пределах целевого домена. Учитываются OU,
которые будут созданы раньше в этом запуске. Неизвестные существующие объекты
считаются конфликтами и не перезаписываются. Совпадение имени учётной записи само
по себе не связывает объекты и не даёт оснований добавлять их в группы.

### Членство в группах
- Члены внутри области миграции: добавляются сразу
- Члены вне области: помечаются DEFERRED; добавляются, когда появляется проверенное соответствие целевому объекту
- DEFERRED закрывается только после подтверждённой записи или чтения уже существующей ссылки; Dry Run не закрывает ссылки
- Большие группы дочитываются последовательными запросами `member;range=...` до конца

При чтении диапазонов проверяются их непрерывность, количество значений и
неизменность `objectGUID`/`uSNChanged`. Ошибка LDAP, пропуск диапазона или изменение
объекта прерывают чтение: частичный состав группы не принимается за полный.
Пагинация списка объектов сохраняется независимо от запросов диапазонов.

### Игнорируемые объекты
- Компьютеры (objectClass=computer)
- Служебные и дефолтные группы и пользователи (определяются по SID)
- Builtin контейнеры
- ForeignSecurityPrincipals
- GPO объекты
- Exchange-специфичные атрибуты


### Workflow

1. Настроить подключения к Source и Destination DC
2. Выбрать одну ветку в дереве домена либо указать Base DN вручную (например: OU=Level2,OU=Level1,DC=source,DC=alt). Вложенные объекты входят в область миграции с учётом исключений
3. **Analyze**: Проанализировать объекты в source. Чтение и проверка целевого домена выполняются в фоне; окно анализа показывает текущий этап и индикатор активности без процентов
4. **Preview**: Просмотреть план миграции (что будет создано/существует/конфликтует)
5. **Start Migration**: Запустить миграцию
6. **Report**: Сгенерировать отчет (опционально)

### Повторные запуски

Повторный запуск использует сохранённые и проверенные соответствия GUID:
- Уже созданные объекты повторно не создаются
- Неотслеживаемые существующие объекты остаются конфликтами
- DEFERRED ссылки разрешаются при появлении проверенных целевых объектов
- В группы добавляются разрешённые ссылки; автоматического удаления лишних участников нет

Это не непрерывная синхронизация каталогов: повторный запуск не гарантирует
обновление всех ранее перенесённых обычных атрибутов. Расхождения выявляются
верификацией и требуют отдельного решения.

### Верификация

После миграции сравниваются конкретные объекты по GUID, значения переносимых
атрибутов после преобразования и ссылки `member`, `manager`, `managedBy`.
Проверяются также родители DEFERRED-ссылок, обработанных в текущем запуске,
даже если они находятся вне выбранной ветки. Количество объектов — справочная
статистика, а не подтверждение полноты переноса.

Потерянные значения, лишние участники и недействительные соответствия — ошибки.
Неразрешённые DEFERRED-ссылки — предупреждения. Детали сохраняются в SQLite и
разделе **Verification details** HTML/TXT-отчёта. Пароли и исключённые системные
атрибуты не сравниваются. `accountExpires` сохраняется точным LDAP-числом;
значения 0 и 9223372036854775807 считаются эквивалентными («никогда»).

Верификация не исправляет расхождения автоматически. Проверяется прямое членство,
а не эффективные права и транзитивный состав групп. В Dry Run содержательная
верификация пропускается.

## Ограничения

- ❌ Перенос исходных паролей: вместо них задаются новые
- ❌ DNS зоны
- ❌ Sites и Subnets
- ❌ GPO (Group Policy Objects)
- ❌ Компьютеры (требуют domain rejoin)

Дополнительные ограничения:
- Контейнеры не создаются: соответствующий путь должен существовать в целевом домене
- Нет атомарного снимка двух каталогов; изменения во время миграции могут потребовать повторного анализа
- Читаются только доступные учётной записи объекты и атрибуты; полнота невидимых данных не гарантируется
- Анализ конфликтов выполняется в пределах домена, а не всего леса

## Безопасность

- Пароли подключений к доменам не сохраняются; фиксированный пароль новых пользователей сохраняется в настройках, поэтому файл конфигурации требует защиты
- Неотслеживаемые существующие объекты в destination не перезаписываются; отслеживаемые объекты могут получать ссылочные изменения
- Детальное логирование всех операций
- Preview перед миграцией
- Dry-run режим

## Логирование

Логи сохраняются в `~/.config/DirectoryObjectsMigrator/logs/migration_YYYYMMDD_HHMMSS.log`

Уровни:
- INFO: Информационные сообщения
- SUCCESS: Успешные операции
- WARNING: Предупреждения (EXISTS, DEFERRED)
- ERROR: Ошибки
- CONFLICT: Конфликты объектов

## База данных
SQLite база данных находится в `~/.config/DirectoryObjectsMigrator/migration.db`

Операции по её очистке и резервному копированию доступны из раздела настройки
соединений. В v1.2 структура обновляется автоматически с созданием резервной копии
перед преобразованием. История и соответствия разделяются по паре исходного и
целевого доменов. Неоднозначные старые записи сохраняются, но не применяются
автоматически.

Сохраните базу при обновлении: после её очистки приложение теряет подтверждённые
соответствия, а существующие целевые объекты становятся конфликтами. Для возврата
к старой версии используйте соответствующую резервную копию базы.

## Отчеты

HTML/TXT-отчёты с детализацией:
- Статистика по типам объектов
- Список созданных/существующих/конфликтующих объектов
- DEFERRED ссылки
- Ошибки и предупреждения

- Конкретные расхождения объектов, атрибутов и ссылок
- Результаты установки паролей, включая резервные попытки, без самих паролей

Отчёты могут содержать DN и персональные данные переносимых объектов.

## Проверки версии 1.3

Пройдены 21 набор автоматических тестов. Выполнена проверка миграции MS AD →
Samba AD с повторными запусками и конфликтами. На Samba проверено полное чтение
двух групп по 1605 участников с явно запрошенным первым диапазоном из 500 значений
и одновременной пагинацией списка групп. Автоматический порог выдачи диапазонов
большой группы на исходном MS AD в этой проверке не проверялся.

Запуск тестов из распакованного архива:

```bash
QT_QPA_PLATFORM=offscreen python3 tests/run_all.py
```
